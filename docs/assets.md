# 資産管理・画面修正の追加仕様

元のv1.1要件への追加・変更です。ユーザーの修正指示と「資産から負債を引いたものを純資産として計算して。自動反映。」に基づきます。

- アプリ名：**セミナー会計　早瀬ユウカ監修　家計簿アプリ**。
- キャッチコピー、英語の飾り見出し、円マークの装飾を削除。画面見出しと機能を中心に表示。備考のプレースホルダーは空欄。
- 金額入力は1文字ずつの追加・削除・途中の編集でも3桁ごとに再整形。小数・負数・不正な貼り付けは拒否。
- 初回は資産管理タブで現金、ゆうちょ銀行、JREBANK、金融資産、SUICA、PayPayを入力。負債はJALカード未払額、JREカード未払額、その他の負債を入力。ない項目は0円。
- 純資産＝資産合計−負債合計。収支の登録・編集・論理削除を残高へ自動反映する。
- 現金・銀行・電子マネーの収入は資産増、支出は資産減。カードの支出は負債増、入金は負債減。
- 残高反映先は支払方法IDへ紐付ける。取引は登録時の反映先をN列に保存し、マッピングを変更しても過去の取引を付け替えない。反映先未設定の新規登録は拒否し、設定方法を表示。
- 金融資産の評価額を含め、各残高は日付付きの確認値を登録できる。履歴を上書きせず、新しい行を追加する。同日複数の確認値は後から登録したものを使用する。
- 銀行から現金、電子マネーへのチャージ、カード返済、借入を「資産移動・返済」として記録する。収入・支出の集計に加えない。取り消しは論理削除。
- 資産・負債・純資産の直近12か月推移をグラフと金額表で表示。過去月は月末、選択月は残高表示日まで。登録前の残高は未登録であり、0円として補完しない。

## 確認値と自動計算

確認日はその日までの入力済み取引を含む、実際の残高・評価額を入力する。開始残高についても同じ規則を使い、旧版で入力済みの収支を二重に反映しない。

確認値の保存時に、同じ確認日の登録済み取引・移動による増減額も保存する。表示残高は、項目ごとの最新の確認値＋確認日以後の現存する取引・移動の増減−保存済みの確認日増減額。この方式により、確認後に追加した同日取引と、同日取引の訂正・取り消しを反映できる。

確認日より前の取引の修正は、それ以後の実際の残高確認値を変更しない。取引日を確認日の前後へ変更した場合は、確認日以後に含まれるかどうかで再計算する。後日登録した確認値がある項目の推移は、その確認値を基準にする。金融資産の評価変動は収入・支出に計上しない。

残高の手動変更は、読み込んだ取引・残高履歴のリビジョンを検証する。他の画面で更新済みなら保存せず、再読み込みを要求する。開始残高・確認値・移動の追加はリクエストIDで重複を防ぐ。

## スプレッドシートの追加

| シート・列 | 内容 |
| --- | --- |
| Transactions N列 `asset_account_id` | 取引に紐付く残高項目ID。A〜Mは維持 |
| AssetAccounts | account_id、name、kind（asset/liability）、sort_order |
| PaymentAccountLinks | payment_method_id、account_id、updated_at |
| AssetSnapshots | snapshot_id、date、balances_json、included_effects_json、created_at、request_id |
| AssetMovements | movement_id、date、from_account_id、to_account_id、amount、created_at、deleted_at、request_id |

確認値を複数項目分まとめて1行へ保存し、開始残高の一部だけが保存されることを避ける。Json内の値も正本のスプレッドシートに保存する。ブラウザの一時領域は、結果不明の送信の再試行にのみ使う。

## 既存データの移行

5つのGASファイルを更新後、`setupDatabase` を一度実行し、新バージョンをデプロイする。既存の取引・設定・残高履歴を消さない。標準支払方法は初期IDで判定するため、名称変更済みでも反映先を設定できる。独自の支払方法は反映先を利用者が選び、未設定の過去取引を編集・保存する。

Googleへの認可・実保存・本人限定アクセス・実機ブラウザでの動作はGoogle上での確認が必要。
